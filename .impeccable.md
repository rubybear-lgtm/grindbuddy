# Grind Buddy — Design Context

## Design Context

### Users
Engineers at any level (student through senior) who are actively practicing LeetCode problems for technical interviews. Mental state: focused and motivated, but aware that grinding randomly doesn't work — they want to study smarter. Time-constrained, impatient with fluff. They respond to tools that feel sharp and purposeful, not toys or generic SaaS.

Job to be done: know exactly what to practice today, track whether they're improving, and build confidence before an interview.

### Brand Personality
**Sharp · Focused · Relentless**

Terse, direct, earned. Like a training tool built by someone who's been through the process. No hype, no hand-holding. Copy should feel like a well-written terminal man page crossed with a focused study guide.

Emotional goal: the user feels *in control* and *clear-headed* — not overwhelmed by 2000 problems. Grind Buddy removes decision fatigue and tells you what to do today.

### Aesthetic Direction
Dark mode is the canonical experience. The authenticated app interior is dark-first. Light mode is a **full first-class experience** — not a palette swap, not an afterthought. Both themes should feel intentional and complete. When designing new UI, verify it in both modes.

**Dark palette:**
- Background: `oklch(0.10 0 0)` — rich black
- Card surface: `oklch(0.14 0.01 165)` — dark with a green tint
- Primary: `oklch(0.85 0.18 165)` — Allium green-teal
- Brand cyan: `oklch(0.75 0.15 190)` — secondary accent
- Brand purple: `oklch(0.65 0.2 300)` — exploratory, no defined role yet; don't lean on it until a use case is established

**Light palette mirrors the same hue family** — warm greens/teals, not cold grays.

**Typography:**
- Headings: Outfit (black weight, uppercase, tight tracking) — use `.text-h1`, `.text-h2`, `.text-h3` utility classes
- Body: Inter
- Data/code: JetBrains Mono

**Layout & motion:**
- Bento grid layouts, glassmorphism panels (`.glass-panel`), subtle shimmer animations
- Geometry over illustrations
- Motion must communicate state or guide attention — decorative animation gets cut
- `shimmer-green` hover effect on primary cards is intentional; don't add more shimmer variants without a reason

**References:** Linear.app (dark, precise, purposeful), Vercel's marketing (technical, developer-native). The existing Grind Buddy UI is the reference.

**Anti-references:**
- Generic SaaS: gradient heroes, stock photos, "revolutionize your workflow" copy
- Enterprise gray dashboards
- Gamified study apps (Duolingo energy, mascots, bright reward colors)
- Infrastructure copy tone (`DEPLOY_AGENT`, `INDEX_PROBLEM`, etc.)

### Design Principles

1. **Copy names the thing.** Say what the feature does — not what it metaphorically resembles. "Due for review" not "Priority Recall Stream." The aesthetic can be bold and technical; the words must be clear.

2. **Visual boldness, verbal restraint.** Heavy type, high contrast, and motion are welcome. Copy should be terse — fewer words, more impact. Never pad a headline.

3. **Respect the user's intelligence.** No tooltips explaining what a streak is. No onboarding for obvious features. Users are engineers who know LeetCode — write for them.

4. **Both themes are first-class.** Light mode is not just a color inversion. When adding UI, check it in both light and dark. The same principles of contrast, hierarchy, and brand character apply in both.

5. **Function first, then delight.** Motion and shimmer serve attention and feedback — not decoration. If an animation doesn't communicate state or guide attention, remove it.
